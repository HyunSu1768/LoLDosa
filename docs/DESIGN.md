# LoLDosa 디자인 원칙과 근거

이 문서는 화면의 모든 결정에 "왜"를 붙여 둔 곳이에요.

**근거는 두 가지예요.**
1. **토스 원칙:** 토스가 공개한 원칙과 실험, 그리고 토스가 배포한 디자인 시스템 코드예요. 자세한 출처는 `reports/토스 디자인 원칙과 적용.md`에 있어요.
2. **사용 맥락:** 플래티넘 정글러가 밴픽 30초, 로딩 화면, 게임 직후에 이 화면을 본다는 점이에요.

**출처 확인 수준 표기**

| 표기 | 뜻 |
|---|---|
| [원문] | 토스 원문에서 확인 |
| [패키지] | 토스가 배포한 npm 코드에서 값을 읽음 |
| [2차] | 2차 자료(책 요약 등) |
| [스니펫] | 검색 요약에서만 확인 |
| [추론] | LoLDosa 쪽 판단 |

규칙 번호(B·H·R·L·S)는 리포트의 화면별 규칙 번호와 같아요. 코드 주석에도 같은 번호를 달았어요.

## 0. 누구를, 언제

| 순간 | 상태 | 디자인이 지켜야 할 것 |
|---|---|---|
| 밴픽 30초 | 롤 클라이언트와 번갈아 봐요. 실제로 읽는 시간은 5초 안팎이에요. | 결론 한 문장, 행동 하나 |
| 로딩 화면 1~2분 | 여유가 있어요. | 근거와 세부를 펼쳐 볼 수 있게 |
| 게임 직후 | 졌으면 기분이 상해 있을 수 있어요. | 공감 한 줄, 고칠 것 하나 |
| 쉬는 시간 | 공부하고 싶은 상태예요. | 개념, 내 기록, 퀴즈 |

## 1. 제품 원칙

### 1.1 한 화면 한 메시지
**출처:** One thing per One page [2차], 해외송금 상태 9개를 3개로 줄인 사례 [원문]

**적용**
- 화면마다 첫 줄에 답하는 질문은 하나예요.
  - 홈: "나 지금 어디쯤이야?"
  - 브리핑: "그래서 이번 판 뭐 해?"
  - 복기: "이 판에서 뭘 배우지?"
- 판단 훈련과 퀴즈는 **한 번에 한 문제**만 보여 줘요. 이전 화면은 장면 4개와 퀴즈 전체를 세로로 늘어놓았어요.
- **왜:** 장면이 여러 개 보이면 하나도 깊게 생각하지 않아요.

### 1.2 3초 안에 답할 수 있게
**출처:** Easy to answer, 보험금 청구 질문을 바꿔 이탈 50% 감소 [원문]

**적용**
- 맨 위에 큰 숫자 하나를 둬요. 홈은 진행도 56px, 브리핑과 복기는 결론 22px 이상이에요.
- 선택지는 이미 아는 말로 써요("귀환해서 정비", "봇 갱").

### 1.3 가치를 먼저, 비용은 나중에
**출처:** Value first, Cost later [2차], "인증은 마지막까지 미룬다" [원문]

**적용**
- 처음 켜면 설정이나 Riot ID 입력부터 시키지 않아요.
- 첫 화면의 버튼은 하나예요. "최근 경기 불러오기"를 누르면 키 없이 롤 클라이언트 전적으로 바로 진단해요.
- API 키는 설정 안쪽에 두고 "없어도 돼요"라고 적어요.
- **왜:** 이전 온보딩은 Riot ID → 목표 고르기를 강제했어요. 결과를 보기 전에 두 번 묻는 셈이었어요.

### 1.4 점진적 공개: 지우지 말고 접는다
**출처:** "우리만 알면 되는 정보인가?" [원문], "쉬운 금융은 위험을 단순화한다"는 비판 [스니펫]

**적용**
- 근거(n=판 수), 카드 전체, 첫 6분 시간표, 비교표, 참고 기록은 지우지 않았어요. **"근거와 세부 보기", "나머지 기록 보기" 시트로 옮겼어요.**
- 근거 판 수는 기본으로 숨기고, 설정에서 켤 수 있어요.
- **왜:** 코칭 앱이 근거를 지우면 믿을 이유가 사라져요. 대신 첫눈에는 결론만 보이게 했어요.

### 1.5 기다림을 없앤다
**출처:** No More Loading [2차], "로딩은 거의 없도록" [원문]

**적용**
- 모든 화면이 스피너 대신 스켈레톤(빈 모양)을 먼저 그려요.
- 경기 불러오기는 진행을 3단계로만 보여 줘요: "경기 불러오는 중 → 분석하는 중 → 다 됐어요"(R5).
- 브리핑은 새 결과가 올 때까지 이전 결과를 그대로 둬요.

### 1.6 기록과 제안은 다른 층에
**출처:** 자산 리포트를 별도 층으로 띄우자 CTR·CVR 각 3배, 표현만 바꾼 안은 1.1배 [원문]

**적용**
- **내 기록:** #202027 리스트에 둬요.
- **앱의 제안:** "이번 주엔 이것 하나만 고쳐 봐요", 브리핑의 다음 판 할 것이 해당돼요. 한 층 위인 #2C2C35에 그림자와 함께 띄워요(`.card.suggest`).
- **왜:** 같은 그리드에 섞여 있으면 제안이 기록처럼 읽혀서 넘겨 버려요.

### 1.7 맥락에 따라 화면이 온다
**출처:** Context-based [2차]

**적용:** 챔피언 선택이 시작되면 어느 화면에 있든 브리핑으로 자동으로 넘어가요. 내비게이션에는 빨간 점이 켜져요.

**왜:** 밴픽 중에 탭을 찾아 누르는 데 쓰는 2초는 30초의 7%예요.

### 1.8 추천은 하나
**출처:** 카드 추천에서 1등 하나만 보여 준 안이 순위 목록을 이김. 저자가 "변수가 잘 통제되진 않았다"는 단서를 닮 [원문]

**적용**
- 홈은 챌린저 차이 3개 대신 **1위 하나**만 보여 줘요. 2·3위는 "왜 이게 1순위예요?" 시트 안에 있어요.
- 브리핑의 픽 추천도 1개를 크게 보여 주고, 후보는 2개까지만 작게 보여 줘요.

## 2. 시각 시스템
값은 모두 [패키지]예요: `@toss/tds-colors@0.1.0`, `@toss/tds-typography@0.0.3`, `@toss/tds-mobile@2.5.1`. 파일은 `static/css/tokens.css`예요.

### 2.1 다크 배경은 층으로

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--bg-sunken` | #101013 | 내비게이션, 입력칸 바탕 |
| `--bg` | #17171C | 화면 바탕 |
| `--bg-layer` | #202027 | 카드, 리스트(내 기록) |
| `--bg-float` | #2C2C35 | 제안 카드, 시트, 토스트 |

**왜:** 다크에서는 그림자가 잘 보이지 않아요. 그래서 TDS는 밝을수록 높은 층으로 위계를 나타내요.

### 2.2 색은 뜻으로만

| 색 | 값 | 쓰임 |
|---|---|---|
| 파랑 | #3485FA | 주요 행동(fill 버튼), 선택, 블루 진영 |
| 초록 | #16BB76 | 통과, 이득 |
| 빨강 | #F04251 | 실패, 손해, 레드 진영 |
| 노랑 | — | 연습 목표, 오브젝트, 주의 |

- **증권식 "빨강=상승, 파랑=하락"은 쓰지 않아요 [추론].**
  - 롤 화면에서 파랑과 빨강은 이미 진영 색이에요.
  - 우리 값은 오르내림이 아니라 좋음과 나쁨이라서 초록과 빨강이 맞아요.
- **회색 글자 단계**

| 단계 | 값 | 쓰임 |
|---|---|---|
| grey900 | #FFFFFF | 제목·숫자 |
| grey700 | #C3C3C6 | 본문 |
| grey600 | #9E9EA4 | 보조 |
| grey500 | #7E7E87 | 라벨 |

### 2.3 타이포
- **크기:** TDS t1~t7 스케일(30/26/22/20/17/15/13px)을 그대로 써요.
  - 히어로 숫자는 56px이에요 [추론]. 데스크톱 창에서 2m 떨어져 봐도 읽히는 크기예요.
- **서체:** Toss Product Sans는 공개 라이선스가 아니라서 Pretendard Variable을 써요.
- **숫자:** `tabular-nums`로 폭을 고정했어요(B7). 점수와 시간이 바뀌어도 글자가 흔들리지 않아요.
- **줄바꿈:** `word-break: keep-all`로 한글 단어 중간에서 줄이 바뀌지 않게 했어요.

### 2.4 버튼
**출처:** TDS Button [패키지]

| 크기 | 높이 | 모서리 |
|---|---|---|
| xl | 56px | 16px |
| l | 48px | 14px |
| m | 38px | 10px |
| s | 32px | 8px |

- 글자 굵기는 600이에요.
- **화면당 fill(파랑)은 하나만 써요.** 나머지는 weak(파랑 옅은 바탕)나 grey예요. **왜:** 다음 단계로 가는 버튼은 하나여야 해요 [원문 2018].

### 2.5 리스트 행
**출처:** TDS ListRow 패턴 [패키지]

**구성:** 높이 64px 이상, 왼쪽 40px 아이콘, 제목 17px, 보조 13px, 오른쪽 값 또는 꺾쇠(›).

**왜 표 대신 행을 쓰나:** 이전 화면의 6열 비교표는 읽는 순서가 정해지지 않았어요. 행은 "이름 → 내 값"을 한 줄에 하나씩 읽게 해요.

### 2.6 모션
**출처:** TDS [패키지]

- 누르면 0.96으로 줄었다가 튀어 돌아와요(`cubic-bezier(.34,1.56,.64,1)`).
- 시트는 아래에서 24px 올라오며 나타나요(expo 이징).
- 호버는 `(hover:hover) and (pointer:fine)`일 때만 적용돼요. 터치 화면에서 호버 자국이 남지 않게 하려는 거예요.

## 3. 문구 원칙
**출처:** 토스 8가지 라이팅 원칙 [원문], 앱인토스 UX 라이팅 가이드 [스니펫]

**`scripts/lint_copy.py`가 CI에서 자동으로 검사하는 규칙**
- 해요체만 써요. 「~습니다」 금지, 「되어요」 대신 「돼요」.
- 명사형 종결을 쓰지 않아요.
  - 「가져감」 대신 「가져갔어요」
  - 「기록 없음」 대신 「아직 기록이 없어요」
- 화살표로 문장을 잇지 않아요.
  - 「봇 유리 → 드래곤 위주」 대신 「봇 라인전이 유리해 보여요. 드래곤 쪽 위주로 운영해요」
- 「취소」 버튼은 쓰지 않아요. 「닫기」를 써요.
- 영어 단위(min, sec)는 쓰지 않아요.

**사람이 지키는 규칙**
- **지시가 아니라 제안으로 써요 (R3).** 「~해야 합니다」 대신 「~해 보세요」.
- **졌을 때는 공감 한 줄을 먼저 써요 (R2).** "아쉬운 판이었어요. 이 판에서 하나만 배운다면…"
- **버튼은 결과를 말해요 (L3).**
  - 「확인」 대신 「연습 목표로 정하기」, 「이 장면 리플레이로 보기」
  - 「저장」 대신 「확인하고 저장하기」
- **빈 문장은 넣지 않아요.** 자리가 비어 보인다는 이유로 설명을 채우지 않아요 [원문].
- **숫자 표기 [추론]:** 토스에는 공개된 규칙이 없어요.
  - 시간은 게임 시계 형식으로 써요(6:18).
  - 천 단위에는 쉼표를 붙여요.
  - 변화량에는 부호를 붙여요(+3점).
  - 퍼센트는 정수로 써요.

## 4. 화면별 결정과 근거

### 홈 (`js/home.js`)

| 요소 | 결정 | 근거 |
|---|---|---|
| 히어로 | "84점" 숫자 하나와 "플래티넘 0 · 챌린저 100" 막대 | H1 숫자 하나. 홈에서 궁금한 건 "어디쯤이야?" 하나예요 |
| 막대 눈금 | 양 끝만 표시하고 중간 티어 눈금은 뺐어요 | 중간 위치는 측정값이 아니에요. 틀린 정보를 그리지 않아요 |
| 변화 | "+3점(앞쪽 판보다)" | H6. 성공은 클릭이 아니라 지표가 바뀌었는지예요 |
| 제안 카드 | 1위 지표 하나만 띄워요. 이번 주 목표는 남은 거리의 1/3이에요 | H3 하나만, H4 다른 층. 한 번에 챌린저까지 가라고 하면 포기해요 |
| 제안 버튼 | fill 「OOO가 하는 거 보기」, weak 「왜 이게 1순위예요?」 | fill 버튼은 하나만. 결과를 말하는 버튼 이름 |
| 기록 리스트 | 복습, 연습 목표, 최근 3판, 새 경기 | H4 내 기록은 리스트 층에 |
| 개념별 달성률 | 홈에서 빼고 "배우기 → 내 실력 지도"로 옮겼어요 | 2018 실험: 첫 화면에 더 넣어도 사용자와 매출은 그대로였어요 [원문] |
| 첫 실행 | 결과를 바로 보여 주는 버튼 하나 | 1.3 가치 먼저 |

### 게임 전 브리핑 (`js/brief.js`)

| 요소 | 결정 | 근거 |
|---|---|---|
| 내 픽 전 | "OOO를 추천해요" 하나 + 후보 2개 + 밴 추천 한 줄 | 1.8 추천은 하나, B5 내 챔프폭 안에서만 |
| 내 픽 후 | 플랜 첫 줄을 22px 결론으로, 나머지는 3줄까지 | B1, B2 |
| 주의 | 실제로 있을 때만 노란 줄 하나 | B6. 항상 떠 있는 경고는 읽히지 않아요 |
| 이번 판 연습 | 챌린저 차이 1위 지표의 연습 한 줄 | 홈의 제안과 같은 내용이에요. 연습이 브리핑까지 이어져요 |
| 팀 목록 | 왼쪽 240px에 고정 | 큰 롤 클라이언트 화면과 같은 위치에 둬서 다시 찾지 않게 했어요 [추론] |
| 근거·카드·시간표 | 「근거와 세부 보기」 시트 안에 | 1.4. 로딩 화면에서 천천히 봐도 돼요 |
| AI 코치 | 버튼으로 상태를 보여 주고, 결과는 시트에 | 10~20초 걸리는 결과로 결론 자리를 밀어내지 않아요 |
| 자동 전환 | 챔선이 시작되면 이 화면으로 | 1.7 |

- **전체 운영 (초반·중반·후반 4줄)**: 지금 할 일(히어로) 아래에 게임 전체 흐름을 시간 순으로 둬요. 한 줄은 그 시간대에 할 일 하나만, 눌러야 세부가 나와요 (B2). 시간은 2026 오브젝트 시계(5:00 드래곤 · 8:00 유충 · 15:00 전령 · 20:00 바론)로 나눴어요. 플레이어가 게임 안에서 실제로 보는 시계라서요.
- **'2026 규칙' 배지와 판단 구분**: 실제 경기 처치 시각으로 확인한 시간표는 파란 배지로, 조합·코칭 자료로 정리한 운영은 배지 없이 둬요. 믿어도 되는 것과 상황 따라 바꿀 것을 섞지 않으려고요.
- **조합 유형은 챔피언 이름으로 설명**: "한타 조합"이라고만 하면 왜인지 모르니 "말파이트·리신·노틸러스가 상대를 잘 묶고 앞에서 맞아 줘요"처럼 이유가 된 챔피언을 같이 보여 줘요.

### 롤 창 옆에 붙기 (`app/dock.py`)
- **왜 붙이나**: 챔피언 선택 중엔 눈이 롤 클라이언트에 있어요. 다른 창으로 전환하면 픽 타이머를 놓쳐요. 클라이언트 바깥쪽에 붙어 있으면 고개만 돌리면 돼요.
- **바깥쪽만**: 클라이언트 위에 겹치면 룬·스킨·채팅을 가려요. 오른쪽에 자리가 없으면 왼쪽, 양쪽 다 300px 미만이면 붙이지 않아요.
- **따라가기와 떼기**: 클라이언트를 옮기면 같이 옮겨요. 사용자가 우리 창을 끌어서 떼면 그 뜻을 존중해서 따라가지 않아요.
- **좁은 화면**: 1080p 가운데 클라이언트 옆은 320px 뿐이라, 600px·400px 이하 레이아웃을 따로 뒀어요 (내비는 아이콘만, 꼬리표는 제목 위로).

### 왜 바꿨나 — 실력이 늘게 하는 장치 (개선 1~5)
- **판단 훈련은 시야 기준**: 문제를 낼 때 상대 정글 실제 위치를 숨기고 '마지막으로 본 곳'만 보여 줘요. 게임 안에서 모르는 걸 알려 주면 판단 연습이 아니라 정답 보기가 돼요. 위치 추적 문제를 먼저 풀어야 행동 문제가 열려요.
- **결과 목표 대신 행동 목표 + 다짐**: "CS 올리기"는 판 안에서 할 수 있는 행동이 아니라서, '골드 들고 다니지 않기', '쉬는 시간 없애기'를 초 단위 기록으로 채점하고 "만약 ~하면 ~해요" 형태 다짐을 브리핑·게임 끝 알림에 이어 붙였어요 (실행 의도 연구).
- **교훈은 영향 큰 순서 + 내 피드백**: 2분 뒤 팀 골드 변화로 영향도를 매기고, '아니에요'가 쌓인 규칙은 1순위에서 빼요. 리플레이에서 확인할 질문을 같이 줘서 스스로 확인하게 해요.
- **지렛대 표시와 내 값의 범위**: 같은 사람 안에서 승률과 이어지지 않은 지표는 우선순위를 낮추고, 판이 적으면 내 값의 흔들림(하위 25%~상위 25%)을 같이 보여 줘요.
- **프로 리플레이엔 볼 것 하나**: 그냥 보면 남는 게 적어서 "다음 30초 동안 핑을 언제 찍는지 세어 보세요"처럼 관찰 과제를 같이 띄워요.
- **주간 AI 리포트**: Claude가 진단·체크·판단 훈련 기록만 근거로 이번 주 고칠 것 하나를 골라요. 근거 id가 없는 문장은 서버에서 버려요.

### AI 코치 준비 (`js/flows.js` claudeSetupSheet)
- **흐름:** 3단계로 보여 줘요: Claude 설치 → Claude 로그인 → AI 코치 사용.
- **진행 방식:** 각 단계마다 버튼은 하나예요. 로그인은 새 창에서 공식 로그인을 띄우고, 3초마다 상태를 확인해 끝나면 바로 알려요.
- **왜 바이너리를 넣지 않나:** Anthropic 약관(legal-and-compliance)상 다른 제품에 넣어 배포하려면 상업 약관 계약이 필요해요. 사용자는 Anthropic 공식 흐름으로 직접 로그인해야 하고, 앱이 토큰을 다루면 안 돼요.
  - 그래서 공식 설치 스크립트를 실행하고, 공식 로그인 창을 띄우고, `claude auth status`로 상태만 읽어요.
- **묻는 빈도:** 앱을 켤 때 하루에 한 번만 물어요. 1.3 가치 먼저 원칙과 같은 이유로, 매번 막아서지 않아요.

## 5. 접근성
**출처:** 토스 A11y Fundamentals [원문]

- **실제 요소를 써요 (S5).** 모든 조작은 `<button>`이나 `<a>`예요. `div onclick`은 쓰지 않아요.
- **키보드:** `:focus-visible` 파란 포커스 링을 보여 줘요.
  - Esc를 누르면 시트가 닫혀요.
  - 시트를 열면 포커스가 시트로 가요.
- **스크린 리더**
  - 시트는 `role="dialog" aria-modal`이에요.
  - 토스트는 `role="status"`, 게임 끝 알림은 `aria-live`예요.
  - 상황판 SVG에는 `aria-label`을 붙이고, 같은 내용을 글자 목록으로도 둬요.
- **색만으로 알리지 않아요.** 통과·실패는 색과 함께 ✓·✗ 또는 글자로도 표시해요.
