# LoLDosa — 정글러 챔피언 선택 브리핑 도구 기획서 (v0.1)

> 딥 인터뷰(2026-10-31) 결과 정리. 결정 사항과 미결 사항을 분리해 기록한다.

## 1. 한 줄 정의

챔피언 선택 단계에서 **로컬 클라이언트(LCU)** 정보를 실시간으로 읽고, **자동 수집·분석 파이프라인이 만든 근거 기반 지식 베이스**를 바탕으로
정글러에게 픽/밴 추천과 게임 운영 브리핑을 제공하는 개인용 데스크톱 앱.

## 3. 브리핑 콘텐츠 (정글 전용)

모든 항목은 **수치 + 표본 수 + 출처**를 달고 나간다. 근거가 부족하면 "데이터 부족"으로 표기하고 추측하지 않는다.

1. **픽/밴 추천** — 아군 조합·공개된 적 픽 기준 정글 후보. 승률, 표본 수, 조합 시너지, 상대 정글 카운터 여부.
2. **동선·첫 시야 플랜**
   - 내 챔피언의 시작 캠프·풀클/3캠프 갱 비율 (고티어 타임라인 기반)
   - 적 정글의 예상 시작 위치와 3분 시점 위치 분포 → 카정·첫 와드 위치 제안
3. **갱킹 타이밍/대상 라인** — 라인별 매치업에서 라인 우선권, 아군 CC·킬각, 2/3/6레벨 파워 스파이크, 고티어 첫 갱 성공률이 높은 라인·시간대.
4. **적 정글 매치업** — 초반 1:1 구도, 카정 가능성, 클리어 속도 비교, 위험 타이밍.
5. **오브젝트 운영** — 유충/드래곤/전령/바론 우선순위, 스폰 타이밍에 맞춘 리셋·루트, 조합 성격(한타/스플릿/포킹)별 승리 플랜.

## 4. 시스템 구조

```
┌──────────────────────────── 오프라인 (내 PC, 상시/주기 실행) ─────────────────────────────┐
│  수집기(Collectors)            가공(ETL)                    분석(Analysis)                 │
│  - Riot API: 랭크 리스트 →     - 정글러 식별               - 챔피언·매치업 통계            │
│    matchId → match/timeline   - 분 단위 위치 → 캠프/구역   - 시작 동선/첫 갱 분포          │
│  - DDragon/CDragon (패치,수치) - 이벤트 정규화(킬/오브젝트) - 오브젝트 타이밍 패턴         │
│  - 프로 대회 데이터            - 패치 태깅                  - 조합 분류                     │
│  - 통계 사이트 / 영상·가이드   - 텍스트 → 주장+출처 추출    - 표본 수·신뢰구간 산출        │
│                     └────────────────▶  로컬 DB (DuckDB: 경기·이벤트 / SQLite: KB 항목)  │
└───────────────────────────────────────────────────────────────────────────────────────────┘
                                                 │ 조회
┌──────────────────────────── 실시간 (챔피언 선택 중) ─────────────────────────────────────┐
│  LCU 감시 (lockfile → WebSocket /lol-champ-select/v1/session)                           │
│     → 상태 변화(픽/밴/스왑) → 근거 조회(DB) → 규칙 기반 카드 생성(즉시)                   │
│     → Claude CLI(구독): 조회된 근거만 입력, 요약·운영 방향 서술 + 출처 인용(스트리밍)       │
│     → 데스크톱 앱 UI (요약 카드 / 상세 근거 펼치기)                                       │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

핵심 원칙
- **숫자는 DB가, 말은 LLM이.** LLM은 조회된 근거 묶음 밖의 사실을 말하지 못하게 프롬프트·검증으로 제한한다. 출처 ID가 없는 문장은 표시하지 않는다.
- **즉시성.** 픽당 ~30초이므로 규칙 기반 카드를 먼저 띄우고 LLM 서술은 뒤따라 스트리밍.
- **패치 인식.** 모든 통계는 패치별로 저장하고 현재 패치에 가중, 표본이 적으면 이전 패치를 표기와 함께 보조 사용.

## 5. 기술 스택 제안

| 영역 | 선택 | 이유 |
|---|---|---|
| 데스크톱 앱 | pywebview 창 + 정적 HTML/JS (빌드 없음) | 로직을 Python 하나로 유지, Windows(WebView2)·macOS(WKWebView) 동일. 창이 없으면 브라우저로 열림 |
| LCU 연동 | Python 백엔드 | 프로세스 인자/lockfile 로 접속, 1초 폴링으로 챔선 세션 감시 |
| 수집·분석 | Python (httpx, polars) | 데이터 분석 생태계 |
| 저장소 | DuckDB: matches(수집) / stats(집계, 앱이 읽음) / pro / guides | 수집과 앱이 서로 잠그지 않도록 파일 분리 |
| 앱 ↔ 분석 연결 | Python 백엔드(LCU 감시·DB 조회·Claude 호출)를 사이드카로 두고, Tauri 앱은 화면만 담당 | 로직을 한 언어로 유지, CLI 로 단독 테스트 가능 |
| AI | Claude Code CLI 헤드리스 (`claude -p --output-format stream-json`), 구독 로그인 사용 | API 키·종량 과금 불필요. 출처 인용 강제 |

## 6. 리스크와 제약 (확인 필요)

1. **Riot 개인 API 키 제한** — 개인 키는 요청 수 제한이 있어 하루 수집량에 상한이 있다. 경기당 match + timeline 2회 호출. 패치 초반에는 표본이 부족할 수 있음 → 표본 수를 항상 노출.
2. **프로 대회 정글 동선 데이터의 한계** — 공개된 프로 데이터(Leaguepedia, Oracle's Elixir 등)는 픽밴·오브젝트·킬 시간은 있지만 분 단위 위치는 거의 없다. 동선 근거는 주로 고티어 솔로랭크 타임라인에서 나오고, 프로 데이터는 픽밴·오브젝트 운영 근거로 쓰는 게 현실적.
3. **크롤링 약관 위험** — 통계 사이트·영상 자막 수집은 사이트 약관을 위반할 수 있다. 개인용이라도 IP 차단·키 정지 위험이 있으므로 낮은 빈도, 캐시, 해당 모듈을 끄고 켤 수 있게 설계. Riot API 결과와 섞지 않고 출처 구분.
4. **Riot 서드파티 정책** — 챔선 단계에서 숨겨진 정보(솔랭의 적 소환사명 등)를 드러내는 기능은 금지 대상. 공개된 픽·밴 정보만 사용.
5. **Claude 구독 사용량 한도** — 구독 플랜은 시간당 사용량 한도가 있고, CLI 실행 시 수 초의 기동 지연이 있다. 규칙 기반 카드를 먼저 띄우고 LLM 서술은 픽 확정 시점 등 필요한 순간에만 호출(디바운스·캐시). LLM이 실패하거나 한도에 걸려도 앱은 카드만으로 동작해야 한다. 구독 인증은 본인이 직접 쓰는 개인용 도구에서 공식 CLI를 통해서만 사용한다(타인에게 배포 시 API 키 방식으로 전환).
6. **"정답"의 정의** — 고티어 통계는 상관관계일 뿐이므로, 승률 차이에 대해 표본 수·신뢰구간을 같이 보여준다.

### 설계 결정 변경
- **Tauri → pywebview**: 로직이 전부 Python 이라 Rust/Node 빌드 체인 없이 한 명령으로 실행되게 했다.
- **통계 사이트 크롤링(OP.GG, lolalytics 등)은 넣지 않음**: 같은 지표를 Riot 원본 타임라인에서 직접 계산하고 있고(표본·기준을 우리가 통제),
  해당 사이트들은 약관상 크롤링을 금지한다. 필요하면 sources/ 아래에 모듈로 추가할 수 있게 구조만 열어 두었다.
- **판단 보류 기준**: 표본 15경기 미만이면 inference(판단)를 만들지 않는다. 승률은 50% 쪽으로 보정(k=15~30)한 값을 함께 쓴다.

### 관측 한계
- 타임라인 위치는 1분 간격 → 시작 캠프(1:00)·초반 동선(3:00)은 위치 기반 분류.
- 킬 없는 갱 시도는 기록되지 않음 → 갱 통계는 '킬이 난 첫 갱' 기준.
- 와드 설치 이벤트에 좌표가 없어 첫 와드 위치 분석은 불가.
- 프로 공개 데이터에는 위치 정보가 없음.

### 다음 후보
- 개인화: 내 경기 타임라인으로 동선·갱 습관 분석 (인터뷰에서 보류)
- 정글 외 포지션 확장
- 수집 규모 확대(개인 키 승인 후 상시 수집)

| 실력을 재는 체크가 4개뿐, 추측으로 만든 체크 다수 | **챌린저 갭.** 33개 후보 지표를 고수(프로·챌린저·마스터+ 1,760판)와 플래티넘(217판)으로 비교했어요. AUC와 이긴 판/진 판 분리 검증을 통과한 13개만 남겼어요. 판정은 챔피언 특성을 보정한 값으로 해요. |
| 무엇을 고쳐야 챌린저가 되는지 모름 | **홈 화면에 보여줘요.** 진행도 점수(플래티넘 0, 챌린저 100), 가장 큰 차이 3개, 이번 주 단계 목표, 흐름 그래프, 챔피언별 진행도. |
| 고수가 실제로 어떻게 하는지 볼 방법이 없음 | **프로 리플레이 본보기.** 지표마다 그걸 잘한 프로 솔랭(최신 패치)을 그 시점 리플레이로 열어요. |
| 복기를 직접 눌러야 함 | **자동 복기.** LCU 로 게임 종료를 감지하고, Riot에 경기가 올라올 때까지 재시도해요. 받으면 복기하고 핵심 하나를 알림으로 띄워요. |
| 밴픽 화면에 이번 판에 뭘 할지가 흩어짐 | **밴픽 화면에 연습 하나.** 챌린저 차이 1위 지표의 연습을 보여줘요. 추천 픽에는 내 챔피언 진행도가 붙어요. |
| 실제 클라이언트 문제를 볼 수 없음 | **진단 기록.** 챔선 응답과 게임 단계 변화를 기록해 zip 으로 내려받게 해요. 챔선 기록은 `--replay` 로 그대로 다시 틀 수 있어요. |
| 설치·키·수집 장벽 | **통계 묶음 + 실행기.** 통계 묶음(bundle/)이 자동으로 설치되고 Data Dragon 도 자동으로 받아요. `.bat`/`.command` 실행기, 설정 화면에서 API 키 입력, GitHub Actions 설치 파일 빌드도 넣었어요. |

**같은 날 추가로 푼 한계**

| 한계 | 해결 |
|---|---|
| 실제 클라이언트 검증 불가 | **가짜 롤 클라이언트로 매 푸시 검증.** 자체 서명 HTTPS, 기본 인증, lockfile, 챔선 녹화본, gameflow, 2999 Live API, 전적 API 를 흉내 내요. CI 가 푸시마다 '챔선 5단계 → 브리핑 → 게임 중 기록 → 종료 → 자동 복기 → 진단 기록'을 두 가지 시나리오로 확인해요. 키가 있을 때와 없을 때예요. |
| 1분 단위 데이터 | **내 게임은 초 단위로 기록.** Live Client Data API 로 레벨 시각, 귀환·구매 시각, 1,200골드 들고 버틴 시간, CS 가 멈춘 구간을 잡아요. 게임 중에는 아무것도 표시하지 않아요. |
| Riot 키가 있어야 복기 | **키 없이 복기.** 롤 클라이언트 전적 API 를 Match-V5 형태로 바꿔서 써요. 내 puuid 도 클라이언트에서 가져와요. 키가 있으면 핑·challenges 지표까지 나와요. |
| 공유 키라 배포 불가 | **사용자 쪽은 키가 필요 없어요.** 통계는 묶음으로 배포하고, 복기는 클라이언트 전적으로 해요. 키는 통계를 만드는 쪽(관리자)만 있으면 돼요. |
| 에메랄드 표본 15판 | **최근 3패치 에메랄드 121판으로 늘렸어요.** 기준표의 에메랄드는 207판이에요. |

- **실제 롤 클라이언트로는 아직 못 돌려 봤어요.** 응답 형태가 실제와 다를 수 있어서, 차이가 나면 진단 기록으로 맞춰야 해요. 특히 아래 둘이 그래요.
  - LCU 전적의 구형 응답 모양
  - 다른 사람 경기 리플레이 다운로드
- **위치·동선:** Live API 에는 위치가 없어서, 동선은 여전히 잴 수 없어요.
